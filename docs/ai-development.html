MÉCANISMES ABSTRAITS / FIELD NOTE

The next abstraction is the development process.

A case for AI-directed building, without confusing generated code with verified software.

GF / RGLAIRVVEvidence
01 / Position

Programming languages may become implementation layers.

I argue that software development is approaching another abstraction shift. In many tasks, the human contribution will increasingly be framing the problem, defining constraints, assembling experiments and accepting or rejecting evidence — while AI generates more of the implementation.

Machine language did not disappear when higher-level languages arrived. It became less often hand-authored. Similarly, Python, Java and C++ may become increasingly generated, inspected and validated artifacts rather than the primary medium through which every engineer expresses intent.

This is a forward-looking thesis, not an established prediction of imminent obsolescence. Serious projects still demand understanding of semantics, memory, performance, architecture and failure modes. A model that writes code does not assume responsibility for the resulting product.

02 / An unusually concrete case

A limited-budget, human-directed engineering study.

The RISC-V VectorPath study provides a tangible record of AI-assisted exploration in a domain where the operator reports not having specialized prior expertise in JSON parser optimization.

The operator describes an intense period of approximately one week, using a roughly US$30/month AI subscription and a personal computer costing under US$800. These are self-reported local input costs, not a verified total-project accounting.

Native execution took place on separate Cloud-V and EPCC RISC-V systems and depended on their availability, toolchains and experiment infrastructure. A modest personal computer did not itself execute those native benchmarks.

The achievement is not proof that AI causes a particular speedup, or that expertise has ceased to matter. It demonstrates a practical workflow by which a person can coordinate sophisticated implementation, testing and research with assistance from AI.

03 / The Linus Torvalds principle

Judge the work and its evidence — not the tool taboo.

In that original mailing-list reply, Torvalds rejected blanket prohibitions on AI-assisted contributions and invoked the absurdity of banning compilers or editors to prove someone's competence. His stated standard was understanding and responsibility, not the absence of sophisticated tools.

That is compatible with a strong case for AI-directed development — but it does not amount to Torvalds endorsing the abolition of programming languages. My further claim about the next abstraction level is my own.

05 / Research boundaries

What this project does — and does not — demonstrate.

Evidence-based outcomes

Native performance and conformance for specific VectorPath configurations, source fingerprints, published reports, positive and negative workload effects.

Claims still requiring a controlled study

How much productivity was caused by AI rather than domain knowledge, target hardware, access to prior software or experiment design; whether another engineer would obtain the same result in the same time.

The bold hypothesis

Intent, specification, validation and release governance may become more central than hand-authoring each implementation line. The timeline and breadth of this transition remain uncertain.
