Un benchmark dépend de sa référence.

A2 gelé. Deux machines RISC-V. Des résultats délimités et reproductibles.

GF / RGLAIRVVEvidence
01 / Mesures principales

Une avance native importante sur la référence testée.

+60,07 %Cloud-V · 1,6007× le débit
+89,46 %EPCC · 1,8946× le débit
DOM · phase de confirmation du Test 106 · moyenne géométrique appariée sur 18 JSON publics · baseline : simdjson 5.0.4 fallback officiel.

Face à l’ancien A2 — et non plus à simdjson officiel — la version gelée varie de +0,001 % sur Cloud-V et −0,041 % sur EPCC. Les deux binaires stable/A2 ont la même empreinte sur chaque machine dans le banc de test.

03 / Profil livré

RVV-VLA, A2, seuil 16 Kio, packed OFF.

Le décodeur Stage 2 stable original est conservé. Les variantes SIMPLE_RUN et NL4 restent expérimentales : elles améliorent les charges très échappées, mais ne gagnent pas universellement sur les JSON publics, notamment sur Cloud-V.

04 / Limites

Des résultats forts, sans prétention universelle.

La référence est le fallback officiel

Pas tous les backends SIMD de simdjson. Le fork VectorPath utilise une base simdjson dérivée différente de la version 5.0.4 de référence.

Régression sur les JSON minuscules

Sur 95 JSON valides de 2 à 110 octets, VectorPath stable atteint 0,6665× du fallback sur Cloud-V et 0,8497× sur EPCC.

La CI GitHub x86 n’est pas une validation RVV native

Le workflow #78 d’un dépôt apparenté a réussi ; il ne certifie pas l’absence de défaut mémoire de la version RVV sur matériel RISC-V.
