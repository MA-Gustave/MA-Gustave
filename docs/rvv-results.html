A benchmark is only as strong as its reference.

Frozen A2 release candidate. Two RISC-V platforms. Reproducible scope.

01 / Primary result

A substantial native performance advantage.

+60.07%Cloud-V · 1.6007× throughput
+89.46%EPCC · 1.8946× throughput
VectorPath stable A2 vs simdjson 5.0.4 official fallback backend; DOM throughput; paired geometric mean across 18 pinned public JSON files in Test 106 confirmation phase.

Comparison that matters

Against our previously measured A2 engine — not against official fallback — the release candidate changed mean DOM throughput by only +0.001% on Cloud-V and −0.041% on EPCC. Each platform's A2 and VectorPath stable executables had identical binary SHA-256 hashes in the test harness.

04 / Boundaries

Strong evidence deserves precise caveats.

Official fallback is not the fastest official SIMD backend

These numbers refer to upstream simdjson 5.0.4's fallback implementation, not every accelerated backend or all architectures. The VectorPath fork is based on a different simdjson-derived source vintage.

Very small JSON may be slower

On 95 tiny valid JSONTestSuite inputs (2–110 bytes), the stable candidate measured 0.6665× of fallback on Cloud-V and 0.8497× on EPCC. Fixed overhead dominates these workloads.

Historical +64.1% was a different experiment

The earlier Cloud-V Test 89 used exploratory JSON and an official VLS256 reference, not Test 106's 18 public files and fallback backend. These headline gains are not direct measures of a regression.

GitHub Actions #78 is not native RVV Valgrind

A related simdjson fork's fuzz/Valgrind workflow passed on x86 at commit 81c6b1c; it did not prove that these exact VectorPath RVV files passed Valgrind on RISC-V hardware. The earlier #74 failure was isolated in later passes but not conclusively diagnosed.
